# Explain every ignore pattern

Each pattern in `.gitignore` needs a `#` comment on the line directly above it. [The check README](../../README.md) shows passing and failing layouts.

## Read the failure

- `.gitignore:3: pattern "dist/" has no explanatory # comment on the line above`: write a comment on line 2 that says why the pattern exists, such as `# Build output, regenerated by the build`.

One comment covers one pattern. A blank line between comment and pattern breaks the pairing, and so does a bare `#`. Also ask whether the pattern is still needed, and delete it if not.

## Check it first

Run `fitness gitignore-why` from the repo root. Exit 0 means every pattern is explained.
