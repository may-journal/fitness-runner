# gitignore-why

Requires every `.gitignore` ignore pattern to be immediately preceded by a `#` comment explaining why it exists, so ignores are never unexplained and stay easy to audit and onboard. Opt-in — not part of `defaultChecks`.

## Enable

Add it to your `.fitnessrc` `checks` list:

```ts
// .fitnessrc.ts
export default { checks: ['gitignore-why'] };
```

## What passes

Every pattern has a `#` comment on the line directly above it:

```gitignore
# Installed dependencies, never committed
node_modules/

# Build output, regenerated by `npm run build`
dist/

# Local env secrets
.env
```

The rule is strict: one comment per pattern, on the line immediately above. Two patterns under one heading each need their own comment — a single comment does not cover both:

```gitignore
# Editor swap files
*.swp
# macOS folder metadata
.DS_Store
```

Blank lines and a file-level header comment are fine as long as each pattern still has an explanatory comment directly above it.

## What fails

Bare patterns with no explanation:

```gitignore
node_modules/
dist/
.env
```

produce one error per pattern:

```
.gitignore:1: pattern "node_modules/" has no explanatory # comment on the line above
.gitignore:2: pattern "dist/" has no explanatory # comment on the line above
.gitignore:3: pattern ".env" has no explanatory # comment on the line above
```

A comment that is not directly above the pattern also fails — here the blank line breaks the pairing, so line 3 is flagged:

```gitignore
# Dependencies

node_modules/
```

Other failures: a bare `#` (no text) above a pattern, another pattern directly above, or a pattern as the very first line.

## Behavior

- Reads `<root>/.gitignore`. When the file is absent, passes with `filesChecked` 0.
- Classifies each line as blank, a `#` comment, or a pattern (any other non-blank line, including `!` negations and `dir/` rules).
- Pass: every pattern line is directly preceded by a non-empty explanatory `#` comment.
- Fail: reports `.gitignore:<lineNumber>: pattern "<text>" has no explanatory # comment on the line above` for each offending pattern.
- `filesChecked` is 1 whenever `.gitignore` is present.
